# 0.5 completion reflection — printing, OLE drag/drop, and Shell integration

## Verdict

**Complete within the approved 0.5 validation scope.** Every acceptance item in
`docs/milestones/0.5.md` has direct current-tree evidence. The final Visual
Studio 2026/MSVC C++20 x64 Debug and Release trees each build all targets and
pass 134/134 tests. Work on 0.6 did not begin before this reflection.

## Requirement evidence

### Product evidence

1. **Printing application.** `examples/printing` displays printer discovery,
   loads/clones DEVMODE and DEVNAMES settings, shows PrintDlgEx, uses one
   application-owned pagination vector, renders through a real printer HDC,
   checks Esc before every page, and distinguishes success, cancellation, and
   failure. Preview remains usable when no printer exists.
2. **Print preview.** The same `PrintPage` objects drive screen and printer
   rendering. Page Up/Down, Home/End, plus/minus, buttons, bounded zoom,
   DPI-derived bounds, system colors, appearance refresh, and a memory-DC GUI
   self-test cover navigation, DPI, theme, High Contrast fallback, and
   deterministic printer-free rendering.
3. **OLE application.** `examples/ole_drag_drop` transfers Unicode text, CF_HDROP
   files, and a registered custom format. It supports a real mouse drag source,
   external drops, copy/move feedback, Esc cancellation through OLE, and
   Ctrl/Shift+Enter keyboard alternatives. It starts with `ole_sta` and revokes
   the target before teardown.
4. **Shell application.** `examples/shell_integration` exposes explicit buttons
   for per-user association register/remove, Jump List install/delete, Recent,
   taskbar progress/overlay, and typed settings save/remove. It uses stable
   identities, reports structured Shell outcomes, clears taskbar state, and
   handles `TaskbarCreated`. Its self-test uses only a PID-scoped HKCU root.
5. **Reference quality.** All three executables have Per-Monitor V2 manifests,
   native keyboard paths and accessible names, no public-network dependency,
   deterministic `--self-test`, manifest validation, and normal CMake targets.

### Reusable library evidence

6. **Printer ownership.** `printing.h`, `printing_native.h`, and
   `printing_settings.h` define physical micrometre units, owned HGLOBAL and
   printer DC state, scoped locks, move-only settings, enumeration/capability
   results, dialogs, native backends, and structured errors.
7. **Pure pagination.** `PaginateContent`, `PrintPageId`, `PrintLayout`,
   `PrintPageRange`, and `PrintPreviewModel` are HWND/printer independent;
   tests prove ranges, units, stable IDs, page selection, and zoom.
8. **Balanced printing.** `PrintJob` owns the document/page transaction.
   `PrintPages` contains render/cancellation exceptions, aborts false/cancelled
   paths, and completes only after EndDoc. `printing_job_test.cpp` injects every
   early native failure, explicit/repeated cancellation, and destructor abort.
9. **OLE lifecycle.** The OLE component implements real `IDataObject`, cloned
   `IEnumFORMATETC`, `IDropSource`, `IDropTarget`, delayed rendering, effect
   negotiation, exception containment, apartment/thread checks, and a move-only
   revoke-once registration. `Application` owns `OleInitialize` for `ole_sta`.
10. **Typed OLE data.** Unicode, CF_HDROP, custom bytes, and delayed bytes use
    copied pointer-free payloads with configurable size/file/path limits and
    COM-defined STGMEDIUM ownership.
11. **Reversible associations.** Pure plans place the extension claim last,
    quote `%1`, mark extension/ProgID ownership, detect foreign conflicts, write
    only under a supplied/per-user root, notify only for production roots, and
    preserve unrelated values on removal.
12. **Jump List/taskbar.** Stable task IDs are encoded in link arguments,
    removed tasks and maximum slots are honored, incomplete transactions abort,
    and delete is explicit. Taskbar state validates values, enforces the UI
    thread, clears overlay/progress, and recreates after Explorer restart.
13. **Settings.** `VersionedSettingsStore` supports DWORD/QWORD/string/binary,
    explicit schemas and limits, writes `SchemaVersion` last, distinguishes
    missing/version/malformed/access/native failure, and removes only named
    owned values without callbacks or global state.
14. **Contracts.** Public header comments, `docs/api.md`, capabilities/API
    indexes, tutorial, recipes, and llms files state Windows/units, ownership,
    apartment/thread, callback, failure, cancellation, security, fallback, and
    reversibility rules. Raw HKEY/HWND/COM/backend inputs remain available.

### Automated evidence

15. **Pure models.** Printing model, OLE effect, association plan, Jump List,
    taskbar model, and settings transition tests run without printers or
    Explorer.
16. **Native printing.** Installed printers/capabilities/settings are queried
    when available; controlled `PrintBackend` fakes deterministically prove
    every balanced success/failure/cancel/exception path without a dialog.
17. **Native OLE.** Tests use real COM data objects/enumerators and STGMEDIUM,
    delayed renderers, target routing, native register/revoke, MTA rejection,
    cross-thread rejection, callback exceptions, repeated revoke, destroyed
    windows, and window close from a reentrant enter callback.
18. **Native Shell.** Settings and associations use PID-scoped HKCU roots with
    RAII cleanup. A temporary protected HKCU DACL deterministically proves
    access denial and is restored before deletion. Real taskbar/Jump List COM
    is exercised when Explorer permits it, otherwise only documented structured
    outcomes are accepted.
19. **Stress.** `mwtl.integration_stress` performs 200 combined print, COM,
    Jump-plan, taskbar, setting, and association lifecycles, verifies the HKCU
    root is absent, and bounds USER/GDI deltas. GUI self-tests add preview/OLE
    resource loops.
20. **Negative paths.** Tests cover oversized and malformed OLE payloads,
    unsupported formats, delayed/cancellation/render exceptions, invalid
    DEVMODE, absent/denied printers, foreign/denied registry state, invalid
    taskbar state, wrong apartment/thread, stale/revoked/destroyed targets, and
    reentrant close without hangs or leaked state.
21. **Approved matrix.** The final VS2026/MSVC 19.51, Windows SDK 10.0.26100.0,
    C++20, x64 Debug and Release runs each passed 134/134 tests. Other matrices
    are explicitly deferred until after 0.8 by the approved roadmap policy.

### Packaging, documentation, and Agent evidence

22. **Components.** Core remains independent. Installed, add_subdirectory, and
    FetchContent consumers compile `mwtl::printing`, `mwtl::ole`, and
    `mwtl::shell`; the full `mwtl.package_consumer` passed in both final runs.
23. **Beginner path.** `docs/tutorials/printing-ole-shell.md` gives exact

24. **Focused recipes.** Eight recipes cover printed pages, shared preview
    pagination, custom OLE data, drop targets, Jump List tasks, taskbar progress,

25. **Retrieval assets.** `docs/capabilities.json`, `docs/examples.json`,
    `docs/api-index.json`, change matrix routing, API docs, website optional
    integrations, both llms-full files, and Win32++ comparison name every 0.5
    surface and its ownership/failure constraints. Metadata/link tests pass.
26. **Agent evals.** Tasks 21–28 and eight `/W4 /permissive- /WX` golden fixtures
    compile against the three components. Negative rubrics reject unbalanced
    print calls, retained HDC/STGMEDIUM/pointers, incorrect apartments,
    reentrant teardown, registry overreach, missing recovery, and invented APIs.

## Defects found

The completion audit found and fixed the following after the feature surfaces
initially appeared complete:

1. A real Shell reference app exposed a public-name collision between the old
   recent-files `SettingsStatus` and new settings store. The unreleased API was
   renamed to `VersionedSettingsStatus`/`VersionedSettingsWriteResult`, keeping
   the 0.1 API source-compatible.
2. The Shell example and manifest/GUI self-test were missing. They now compose
   every Shell/settings surface and isolate self-test registry state.
3. Agent/document indexes described 37 examples after 38 existed; manifests,
   tutorial, recipes, site, llms, capability/API indexes, comparison, and 28-task
   eval suite were synchronized and validated.
4. There was no combined lifecycle stress test. A 200-iteration test now covers
   print/COM/taskbar/registry cleanup and resource deltas.
5. Printing had safe internal aborts but no application-triggerable cancel
   hook, and the reference did not visibly enumerate printers. A pre-page
   cancellation callback, Esc workflow, enumeration status, and exception tests
   were added.
6. Negative coverage tolerated rather than forced registry access denial, and
   omitted oversized builder input and close-from-drop-callback. A temporary
   protected HKCU root, explicit bounds test, and reentrant close test now prove
   those paths. An unsafe HKLM approach was rejected and not executed.
7. The Win32++ comparison still called completed 0.4/0.5 work planned. It now
   reports supported/composed status with executable and test evidence.

## Known limitations

- Printing cannot guarantee a physical page was produced because automated
  tests must not consume paper or require a configured virtual printer. Real
  printer enumeration/settings/capability APIs run when available, while the
  controlled backend proves exact native transaction behavior. The reference
  invokes the real printer backend manually, so the scenario remains complete.
- Jump Lists, Recent, taskbar overlays, and printer dialogs depend on Explorer,
  policy, installed services, and user choice. The contract requires structured
  unavailable/rejected/cancelled/failure outcomes, not fake success; tests accept
  only those enumerated outcomes and exercise pure plans regardless.
- Esc cancellation is checked between pages, not inside an application render
  callback. Renderers that perform lengthy work should also check their own
  application cancellation token. This does not violate the page-level
  cancellation contract.
- ARM64, VS2022, clang-cl, sanitizers, coverage, Pipeline, and GitHub Actions are
  not evidence for this milestone. They are deliberately deferred to the
  post-0.8 compatibility/CI phase and are not claimed here.

## Thoroughly complete?

**Yes, for the exact approved 0.5 scope.** Every checklist item maps to a public
surface, reference executable, deterministic automated evidence, or explicit
native fallback result; the final current tree passes the complete approved
Debug and Release gates. Audit-discovered defects were fixed and reverified,
not converted into caveats. It is justified to mark 0.5 complete and begin 0.6.
