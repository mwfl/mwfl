# 0.4 completion reflection — rendering and third-party HWND integrations

## Verdict

**Complete within the explicitly approved 0.4 validation scope.** All product,
library, test, packaging, documentation, and Agent requirements in
`docs/milestones/0.4.md` have direct current-tree evidence. The unified
Visual Studio 2026/MSVC x64 Debug and Release configurations each build every
0.4 component and pass all 126 tests. Work on 0.5 did not begin before this
reflection.

## Requirement evidence

### Product evidence

1. **Browser.** `examples/browser` uses optional `mwfl::webview2` and proves
   structured missing-Runtime guidance, asynchronous environment/controller
   creation, address navigation, retained resize/DPI bounds, focus transfer,
   Ctrl+L accelerator handoff, posted process recovery through `Restart`, and
   repeatable `Close`. `mwfl.browser_gui` is an offline `NavigateToString`
   self-test; `mwfl.webview2_native` creates a real controller.
2. **Code editor.** `examples/code_editor` uses optional pinned Scintilla and
   proves strict Unicode file I/O, editor commands, typed notifications,
   find/replace, save-point-backed dirty state, DPI reconfiguration, MSAA names,
   and atomic load/save. `mwfl.code_editor_gui`, `mwfl.scintilla_native`, and
   `mwfl.scintilla_text` cover the executable, HWND, and conversion layers.
3. **Drawing.** `examples/drawing` stores CPU-owned DIP strokes, renders through
   `D2DHost`, handles input/resize/DPI/theme/High Contrast and target discard,
   and exports SVG. Model, native-resource, and GUI tests cover recovery and
   application data independently.
4. **Image viewer.** `examples/image_viewer` uses bounded WIC decode and a
   disposable D2D bitmap cache. Model/decode/GUI tests prove Fit, anchored zoom,
   pan, large-image rejection, DPI coordinates, profile metadata/sRGB policy,
   system backgrounds, and cache recreation.
5. **Reference-app quality.** All four applications use native focusable
   controls, accessible names, retained DPI layout, explicit optional targets,
   Per-Monitor V2 manifests, and deterministic `--self-test` paths. The final
   manifest suite includes Drawing, Image Viewer, Code Editor, and Browser.

### Reusable library evidence

6. **Generic HWND host.** `NativeHost` owns its container and borrows one
   same-thread/process direct child. Its model/native tests cover attach/detach,
   normal parent destruction, focus, tab styles, resize/DPI, notification,
   command/context forwarding, child-first destruction, subclass removal,
   invalid thread/parent inputs, stress, and raw HWND access.
7. **Async/COM helpers.** `UniqueSubscription` and `AsyncInitialization` are
   move-only owners/coordinators. `mwfl.async` proves exactly-once revocation,
   exception containment, success/failure/cancel/close, stale tickets, nested
   dispatch, wrong-thread rejection, owner-first teardown, and races. WebView2
   consumes the same ticket contract for pending callbacks.
8. **WebView2 isolation.** `MWFL_BUILD_WEBVIEW2` defaults off. Enabling it fetches
   only official SDK `1.0.4129.50` with SHA-256 verification, creates
   `mwfl::webview2`, exposes structured Runtime/initialization state, and uses
   an installed static-loader target. Core subdirectory/FetchContent consumers
   do not fetch or expose it.
9. **Scintilla isolation.** `MWFL_BUILD_SCINTILLA` defaults off. Official 5.6.5
   source/runtime archives and hashes are fixed. `ScintillaRuntime` shares module
   lifetime with editors; public text is strict UTF-16/UTF-8; positions are
   UTF-8 bytes; typed notifications and native document/loader ownership are
   documented.
10. **Direct2D lifecycle.** `D2DHost` owns its factory, HWND target, and the full
    BeginDraw/EndDraw transaction. Create/discard/paint callbacks are contained;
    `D2DERR_RECREATE_TARGET` transitions through a tested device-loss model and
    recreates on the next render.
11. **Direct3D lifecycle.** `D3DHost` owns device/context/swap chain/back buffer,
    uses on-demand `RenderFrame`, and returns presented/minimized/occluded/
    device-recreated/failed results. Native tests cover WARP, resize, minimize,
    occlusion, device loss, reentrant resize, close-during-render, and stress.
12. **Contract documentation.** Public headers, `docs/api.md`, focused recipes,
    tutorials, API index, Agent reference, and `llms-full.txt` state errors,
    thread/apartment rules, callback/borrowed lifetimes, reentrancy, DIP/pixel
    units, BGRA8/premultiplied assumptions, Windows 10+, missing dependency and
    hardware fallback behavior, plus raw escape-hatch boundaries.

### Automated evidence

13. **Pure models.** Tests cover `NativeHostStateModel`, async cancellation,
    drawing strokes, `ImageViewportModel`, document dirty transitions,
    `D2DRenderStateModel`, and `D3DRenderStateModel` without third-party HWNDs,
    a GPU, WebView2 Runtime, or Scintilla.
14. **Native HWND evidence.** NativeHost and Scintilla tests inspect real parent/
    child relationships, geometry, focus, tab behavior, forwarded results,
    MSAA names, subclass teardown, runtime lifetime, and destruction ordering.
15. **Rendering evidence.** D2D and D3D native tests create real resources and
    use deterministic models/fallbacks for exceptional states. They cover
    resize/minimize/occlusion/device recreation, paint exceptions, reentrancy,
    close during render, and repeat creation.
16. **Async failure matrix.** `mwfl.async`, `mwfl.webview2_model`, and
    `mwfl.webview2_native` jointly cover immediate/delayed success, missing
    Runtime, explicit HRESULT failure, cancellation before delivery, nested
    dispatch, callback exceptions, owner-first destruction, pending-close, and
    repeated controller restart.
17. **Stress.** NativeHost, Scintilla, D2D, and D3D tests loop creation/teardown
    with bounded native resources. Async subscriptions loop and revoke exactly
    once. WebView2 creates the initial controller plus five successive restarted
    controllers, then separately closes during pending creation.
18. **Unattended determinism.** GUI self-tests use temporary local files or
    in-memory HTML, never require a dialog or network, and return exact exit
    codes. Missing Runtime and hardware/WARP outcomes are structured paths, not
    hangs or unconditional skips.
19. **Approved local matrix.** The unified `vs2026-x64-0.4` preset enables both
    third-party components. Complete Debug and Release builds and all 126 tests
    pass. Package and documentation gates are part of both runs. Per user
    direction, other compilers, architectures, sanitizers, coverage, Pipeline,
    and GitHub Actions are deferred until after 0.8 rather than falsely claimed.

### Packaging, documentation, and Agent evidence

20. **Package isolation.** The installed package independently consumes core,
    D2D, D3D, imaging, Scintilla, and WebView2. It verifies the pinned Scintilla
    DLL and WebView2 static loader. Default subdirectory and FetchContent core
    consumers build without either optional download or linkage.
21. **Beginner tutorials.** Browser, Code Editor, Drawing, and Image Viewer
    tutorials start with Visual Studio 2026/MSVC C++20 x64 commands, explain
    component linkage and deployment, show ownership/thread rules, and provide
    offline focused tests and precise missing-dependency behavior.
22. **Focused recipes.** `native-host.md`, `webview2-navigation.md`,
    `scintilla-notification.md`, `direct2d-drawing.md`, and
    `direct3d-swap-chain.md` use real public APIs and explicitly reject the
    corresponding ownership/reentrancy mistakes.
23. **Retrieval surfaces.** `capabilities.json`, `examples.json`,
    `api-index.json`, `docs/api.md`, website optional-integration/build pages,
    both `llms-full.txt` copies, README/example catalogs, and the Win32++ roadmap
    describe all shipped 0.4 surfaces with component, ownership, threading, and
    fallback constraints. Link/catalog/API/Agent verifiers pass.
24. **Agent evals.** The suite now has 20 tasks. Five 0.4 tasks cover HWND host,
    WebView2 navigation, Scintilla notification, D2D scene, and D3D recovery.
    Their golden fixtures compile in the unified preset with strict warnings;
    every task includes dependency/lifetime negative cases checked by
    `mwfl.agent_evals`.

## Defects found

1. The first unified Debug audit failed `mwfl.build_budget`: the old 150 KiB
   rule counted newly isolated optional headers as core growth. Raising the
   ceiling would have hidden the distinction. The verifier now keeps the core
   at 150 KiB, caps every optional header at 8 KiB, and caps their aggregate at
   32 KiB. The corrected gate passes in Debug and Release.
2. Drawing, Image Viewer, Code Editor, and Browser embedded the shared manifest
   through `mwfl_add_example`, but the manifest test list stopped at Explorer.
   All four are now included with conditional target handling, adding four
   direct executable checks.
3. WebView2 assigned an MSAA name but no test read it through
   `AccessibleObjectFromWindow`. The native test now reads and compares the real
   client accessible name.
4. One WebView2 restart proved recovery but was weak stress evidence. The native
   test now creates six sequential real controllers, performs offline navigation
   after each recreation, and separately proves close-during-pending suppresses
   a late callback.
5. The documentation still reported 31 examples after Drawing, Image Viewer,
   Code Editor, and Browser brought the actual total to 35. README, example
   catalog, website statistics, and machine-readable entries now agree.
6. Separate Scintilla and WebView2 presets could pass while never proving the
   two installed components coexist. `vs2026-x64-0.4` now enables both and is
   the sole final 0.4 gate.

## Known limitations

- The Evergreen WebView2 Runtime is an operating-system/application deployment
  prerequisite, not bundled by mwfl. Its absence is a tested structured result
  with user guidance, so it does not violate optional integration acceptance.
- The current approved validation and third-party binary deployment are x64.
  ARM64, VS2022, clang-cl, ASan/static analysis/coverage, and remote workflows
  are deliberately queued for the post-0.8 matrix pass. No 0.4 claim relies on
  them.
- Browser tests deliberately do not prove public internet availability; they
  prove navigation mechanics with in-memory HTML. Network policy belongs to
  each application and is outside a UI host's contract.
- Direct3D may use WARP when hardware creation is unavailable. The adapter path
  and structured result are explicit and tested, satisfying rather than
  weakening the fallback requirement.
- Scintilla raw `Send` and WebView2 raw COM escape hatches remain intentionally
  low-level and borrowed. Safe high-level operations are tested; callers using
  escape hatches accept the pinned upstream contract.

## Thoroughly complete?

**Yes, for 0.4's approved scope.** Every checklist item has direct evidence,
the first apparent completion was rejected by a real full-suite failure, the
resulting defect and three additional evidence gaps were fixed, and fresh
unified Debug and Release runs both pass all 126 tests. The explicitly deferred
post-0.8 compatibility/CI matrix is documented as deferred work and is not
being misrepresented as verified. It is now valid to mark 0.4 complete and only
then begin 0.5.
