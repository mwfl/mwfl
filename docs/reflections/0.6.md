# 0.6 completion reflection — modern multi-document workspace

> Historical snapshot: see the [current support evidence](README.md) before
> relying on deferred-work notes in this milestone record.

## Verdict

**Complete within the approved 0.6 validation scope.** The library now has a
pointer-free multi-document model, active-document coordination, native tab
projection, rollback-safe cross-window transfer, coordinated close, and bounded
versioned session persistence. The reference application composes those pieces
across two top-level windows. The final approved gate is Visual Studio 2026,
MSVC C++20, x64 Debug and Release; broader toolchains and CI remain post-0.8
work.

## Requirement evidence

### Product evidence

1. **Complete document workflow.** `examples/document_workspace` creates,
   opens, edits, saves, closes, reopens, reorders, and switches Unicode text
   documents. `DocumentId` remains stable while application-owned buffers,
   `TextHistory`, selection, view state, path, dirty state, and file stamps stay
   independent per document.
2. **One active context.** Its menu, toolbar, accelerators, status bar, title,
   save/undo/redo/close/move actions, and tab selection all project through
   `ActiveDocumentCoordinator`; native tab `lParam` stores only the integer ID.
3. **Two-window transfer.** Two real top-level `WorkspaceWindow` instances use
   `TransferDocumentWithPage`. Source ownership remains intact until destination
   model and HWND adoption succeed; rejection rolls back model order, active
   state, page parent, focus, and command projection without a global singleton.
4. **Safe sessions.** `document_session` writes a bounded, tagged, versioned
   format atomically and restores one record at a time through application
   callbacks. The example persists normal runs under LocalAppData, validates
   `FileStamp`, skips missing/changed/untrusted paths, rejects malformed state,
   and creates a safe default document when nothing can be restored.
5. **Recently closed.** `DocumentWorkspaceModel` has bounded deterministic
   close history and preserves stable identity/view metadata. Reopen handles
   duplicates and already-open paths explicitly; missing or renamed paths are
   application validation outcomes rather than silent replacement.
6. **Coordinated shutdown.** `PrepareCoordinatedClose` inspects all workspaces
   before mutation, deduplicates logical documents, and applies save/discard/
   cancel decisions only after the complete plan is accepted. Sync and async
   commit paths preserve ownership on cancellation, callback failure, or retry.
7. **Reference quality.** The example is Per-Monitor V2, keyboard operable,
   names native tab/page/status boundaries for accessibility, builds as a normal
   distributable target, and has an offline hidden `--self-test` covering real
   file, external-change, transfer, recent, session, and teardown workflows.

### Reusable library evidence

8. **Explicit models.** `document_workspace.h` defines nonzero `DocumentId` and
   `WorkspaceId`, metadata/view snapshots, ordering, active state, dirty state,
   recently closed history, transfer plans, and typed operation results.
9. **Application ownership.** Models own metadata copies only. Contents, undo
   buffers, and HWNDs remain application-owned; no base document/view type and
   no object pointer in native item data is required.
10. **Command composition.** `document_coordination.h` projects enabled,
    checked, text, shortcut, undo/redo, and status state into `CommandSet`.
    Callbacks run without model locks and active state is explicit per
    coordinator, including exception and reentrant activation tests.
11. **Native adapter.** `DocumentTabWorkspaceAdapter` borrows `TabControl` and
    sibling page HWNDs, stores stable IDs, synchronizes selection/reorder,
    arranges pages after pixel/DPI layout changes, restores focus, validates
    thread/process/parenting, and reports stale windows. Native tests exercise
    keyboard selection, adoption, teardown, and bounded USER/GDI deltas; the
    application supplies accessible names and close/reorder commands.
12. **Transactional transfer.** `PrepareTransfer`, destination acceptance,
    `CommitTransfer`, and rollback are separate operations. Both pure and native
    tests force duplicate-path rejection and verify source order, active state,
    ownership, parent HWND, and focus remain valid.
13. **Persistence contract.** `document_session.h` bounds files, records, UTF-8
    byte lengths, and fields; supports v0-to-v1 migration and unknown optional
    `X` fields; rejects unknown required versions, malformed, duplicate,
    truncated, and oversized input; and invokes restore validators outside I/O.
14. **Coordinated close contract.** Inspection, decision, and commit are
    explicit. Async saves return before ownership mutation; callback throws,
    reentrancy, window removal, repeated close, cancellation, and retry produce
    typed failures or a still-owned document set.
15. **Public contracts.** Header comments plus `docs/api.md`, the tutorial, and
    recipe state Windows 10+, UI-thread, ownership/lifetime, reentrancy,
    persistence/security, raw HWND, composition, and failure rules.

### Automated evidence

16. **Pure coverage.** `mwfl.document_workspace`,
    `mwfl.document_coordination`, and `mwfl.document_session` cover stable IDs,
    mutations, fallback activation, undo projection, history bounds, duplicate
    paths, transfers, migrations, sessions, and close plans.
17. **Native coverage.** `mwfl.document_tabs_native`,
    `mwfl.window_quit_policy`, `mwfl.advanced.dpi_change`, and
    `mwfl.document_workspace_gui` cover keyboard/native selection, accessible
    application boundaries, focus, parenting/adoption, resize/DPI routing,
    two-window movement, stale HWNDs, auxiliary windows, and teardown order.
18. **Persistence coverage.** `mwfl.document_session` and the GUI self-test use
    unique temporary files and cover round trips, migration/unknown versions,
    malformed/oversized/truncated input, missing/changed/untrusted files,
    duplicates, atomic replacement failure, incremental restore, and cleanup.
19. **Lifecycle and stress.** `mwfl.document_workspace_stress` performs 250
    deterministic open/reorder/transfer/close/reopen/session/close-plan cycles.
    Native and GUI tests add repeated window/page teardown and bounded HWND,
    USER, GDI, file, and callback state.
20. **Exception and race safety.** Coordination/session/workspace/native tests
    force save, restore, routing, validator, adoption, and transfer failures;
    callback mutation/reentrancy, repeated close, stale pages, and post-close
    wakeup/lifecycle suites prove exceptions do not cross Win32 callbacks and
    ownership is not half committed.
21. **Approved local matrix.** Visual Studio 2026/MSVC C++20 x64 Debug and
    Release build and run all 141 tests, including package consumers and docs.
    VS2022, ARM64, clang-cl, sanitizers, coverage, Pipeline, and GitHub Actions
    are deliberately deferred until after 0.8.

### Packaging, documentation, and Agent evidence

22. **Component boundaries.** Workspace/model/session/tab/coordination surfaces
    stay in core and acquire no rendering, OLE, or Shell dependency. Installed,
    add_subdirectory, and FetchContent package consumers compile them.
23. **Beginner path.** `docs/tutorials/document-workspace.md` gives VS2026 x64
    configure/build/run/test commands and incrementally explains ownership,
    commands, rollback, identity, persistence, close, and diagnostics.
24. **Focused recipes.** `docs/recipes/multi-document-workspace.md` has focused
    sections for document types, active commands, undo, closable/reorderable
    tabs, movement, recent history, restore, and coordinated shutdown.
25. **Retrieval assets.** Capabilities, examples, API index, website, both llms
    corpora, change matrix, API docs, and Win32++ comparison name the 0.6
    surfaces, constraints, evidence, and validation commands.
26. **Agent eval.** Task 29 and its `/W4 /permissive- /WX` golden fixture compile
    the intended composition. Its rubric rejects pointer-backed identities,
    hidden active globals, forced Document/View inheritance, premature source
    removal, non-atomic sessions, stale callbacks, and partial shutdown.

## Defects found

1. The Release-only `mwfl.window_quit_policy` test posted `WM_QUIT` during
   `WM_CREATE`, before the message loop was running. It could hang and leave GUI
   test processes behind. The test now posts a private `WM_APP` request, performs
   auxiliary-window destruction from the running loop, then exits. The fixed
   Release binary passed 20 consecutive repetitions before the full gate.
2. README and website example totals remained at 35. The README table omitted
   the three 0.5 reference applications as well as the new 0.6 application.
   Both totals now match all 39 records in `docs/examples.json`, and the table
   links Printing, OLE drag/drop, Shell integration, and Document workspace.
3. Early sandboxed validation produced 16 false failures because Windows SDK
   discovery and native desktop access were denied. The same Debug tree passed
   141/141 outside that restriction, proving these were environment failures;
   final evidence uses the approved local VS environment only.
4. Advancing the roadmap exposed that 0.7 had no acceptance checklist, so the
   metadata validator correctly rejected an active empty milestone. A detailed
   docking contract now exists at `docs/milestones/0.7.md`; 0.6 remains complete
   and the single active roadmap pointer advances consistently to 0.7.

## Known limitations

- Session persistence intentionally stores metadata and safely restorable
  file-backed documents, not application document contents. Untitled or dirty
  contents remain application-owned and require save/discard/cancel before
  shutdown. Tests prove skipped/invalid records cannot replace live ownership,
  which satisfies rather than weakens the ownership contract.
- The native adapter supports same-process, same-UI-thread sibling page HWNDs;
  cross-thread/process adoption is rejected. That is the documented safe Win32
  boundary and does not restrict the required two-window scenario.
- Standard Windows tab accessibility and DPI behavior are composed rather than
  reimplemented. The reference explicitly names native boundaries, keyboard and
  focus tests use the real control, and the full gate includes WM_DPICHANGED plus
  page rearrangement evidence.
- VS2022, ARM64, clang-cl, sanitizers, coverage, Pipeline, and GitHub Actions are
  not claimed as 0.6 evidence. They remain scheduled for the post-0.8
  compatibility/CI phase as explicitly approved.

## Thoroughly complete?

**Yes, for the exact approved 0.6 scope.** Every checklist item has current-tree
implementation, reference-application, test, package, or documentation evidence.
The audit found real Release lifecycle and documentation defects; both were
fixed and reverified rather than waived. It is justified to mark 0.6 complete
and begin 0.7.
