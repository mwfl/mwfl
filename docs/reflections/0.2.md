# 0.2 completion reflection — real SDI application

> Historical snapshot: see the [current support evidence](README.md) before
> relying on deferred-work notes in this milestone record.

## Requirement evidence

### Product

- [`examples/notepad/main.cpp`](../../examples/notepad/main.cpp) is a real SDI
  editor, not a mock-up. It implements New, Open, Save, Save As, Exit, safe
  dirty-document prompts, cancel/discard/save decisions, atomic file writes,
  external-change detection, drag-and-drop opening, recent files, persistent
  settings, and single-instance file activation.
- Editing includes cut/copy/paste, undo/redo, select all, find/replace, menu,
  toolbar, shortcuts, and a status bar driven from one `CommandSet`. The
  Always-on-Top setting proves checked command state and versioned persistence
  against the actual `WS_EX_TOPMOST` native state.
- The application supplies mnemonics and accessible names, uses the native
  system font, relayouts on DPI changes, refreshes for theme/high-contrast
  changes, and declares Per-Monitor-V2 awareness.
- [`examples/notepad/CMakeLists.txt`](../../examples/notepad/CMakeLists.txt)
  installs the executable. The package test verifies that it is present when
  examples are enabled, while library-only builds remain valid.

### Reusable library

- [`include/mwfl/document.h`](../../include/mwfl/document.h) and
  [`tests/document_test.cpp`](../../tests/document_test.cpp) provide and verify
  document identity, path, display name, dirty state, and every unsaved-change
  decision without coupling applications to a Document/View framework.
- [`include/mwfl/text_file.h`](../../include/mwfl/text_file.h) provides explicit
  success, cancellation/failure, encoding, native-error, and externally-changed
  results. Its implementation performs replace-based atomic writes so a failed
  save does not silently destroy the old file.
- [`include/mwfl/command.h`](../../include/mwfl/command.h),
  [`include/mwfl/command_controls.h`](../../include/mwfl/command_controls.h),
  and [`include/mwfl/desktop.h`](../../include/mwfl/desktop.h) propagate text,
  enabled, checked, visible, image, and shortcut state to native menu and
  toolbar surfaces; the status bar participates in normal layout and DPI work.
- [`include/mwfl/recent_files.h`](../../include/mwfl/recent_files.h) uses an
  explicit versioned registry schema and caller-owned key. Missing, malformed,
  and inaccessible data have observable outcomes.
- [`include/mwfl/single_instance.h`](../../include/mwfl/single_instance.h)
  defines primary/secondary ownership, activation delivery, receiver readiness,
  timeouts, and shutdown behavior rather than hiding process-wide state.
- Text search and undo models are separately reusable through
  [`include/mwfl/text_search.h`](../../include/mwfl/text_search.h) and
  [`include/mwfl/text_history.h`](../../include/mwfl/text_history.h).

## Defects found

The completion audit found material defects after the application first looked
complete:

1. A path was retained through a non-owning view; ownership was corrected.
2. Attaching a native menu discarded the handle needed for later updates, and
   rebuilding could leak/reuse menu state. Handle retention, replacement, and a
   200-cycle resource test were added.
3. Programmatic edit changes did not emit the same notification as user edits,
   so the GUI self-test initially overstated dirty-state coverage. The test now
   drives the real state transition.
4. The first DPI assertion compared equivalent effective DPI values. It now
   proves that the actual native font is replaced for a changed DPI.
5. A stale binary could make a GUI test appear green. A per-run diagnostic file
   and explicit process/result checks now bind the result to the launched build.
6. Aggregate success/error results relied on partial initialization accepted by
   MSVC but diagnosed by clang-cl. Every result is now fully initialized.
7. The ASan library-only configuration incorrectly required the optional
   Notepad executable in its installed tree. Package verification now receives
   the actual target-existence expectation and both branches are tested.
8. The hosted clang-cl environment cannot reliably activate GUI executables.
   The new Notepad GUI test initially missed the existing exclusion policy; the
   clang job now runs all non-GUI tests, while both MSVC matrices run the real
   GUI test.
9. Persistent-setting GUI coverage could mutate a developer's registry. The
   self-test uses an isolated instance and skips user writes; versioned registry
   round trips remain covered by the focused registry test.

## Known limitations intentionally deferred

- Notepad is intentionally a plain-text SDI proof application. Rich text,
  printing, shell Jump Lists, multi-document workspaces, and docking belong to
  later accepted milestones; none is required by the 0.2 SDI contract.
- clang-cl hosted runners provide compile and non-GUI runtime evidence, not GUI
  activation evidence. The identical source is built by clang-cl and its GUI
  behavior is exercised in VS 2022/2026 MSVC jobs, so this does not leave a 0.2
  product path untested.
- Registry writes are not performed by the Notepad self-test. The reusable
  persistence layer has isolated registry round-trip and malformed-data tests,
  while the GUI test proves the command/native-window synchronization without
  contaminating a user profile.

## Thoroughly complete

Yes. Every 0.2 acceptance checkbox has direct product, API, focused-test,
real-window, package, documentation, Agent, and compiler-matrix evidence. The
audit found and corrected failures that a simple green unit suite would have
missed, and the remaining limitations are explicitly outside the 0.2 boundary.
0.2 is therefore thoroughly complete, and 0.3 may begin.
