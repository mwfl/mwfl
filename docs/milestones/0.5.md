# 0.5 acceptance checklist — printing, OLE drag/drop, and Shell integration

0.5 is complete only when every requirement below has direct evidence. A demo
that invokes a common dialog, accepts `WM_DROPFILES`, or writes one registry
value does not prove a reusable print, OLE, or Shell lifecycle.

## Product evidence

- [x] A print-capable document reference application enumerates printers,
  configures page/job settings, paginates application-owned content, prints to
  a real or virtual printer, cancels safely, reports failure, and never makes
  preview state authoritative.
- [x] A print-preview reference workflow renders the same pagination model used
  by printing, supports page navigation and zoom, handles DPI/theme/High
  Contrast, and has a deterministic non-printer fallback/self-test.
- [x] An OLE drag/drop reference application supports Unicode text, file lists,
  at least one application-defined format, internal and external drag sources,
  drop feedback/effects, cancellation, and keyboard-accessible alternatives.
- [x] A Shell-integrated reference application proves explicit file-association
  registration/removal, Jump List tasks/recent destinations, taskbar progress/
  overlay behavior, and structured availability/failure without silently
  mutating machine-wide state.
- [x] Reference applications are useful beyond screenshots, Per-Monitor V2,
  keyboard operable, accessible at native boundaries, distributable, and have
  deterministic self-tests requiring no user input or public network.

## Reusable library evidence

- [x] Printer APIs define owned printer/DC/global-memory handles, DEVMODE/
  DEVNAMES locking, enumeration, capability queries, page setup/print dialog
  results, document/page transactions, cancellation, errors, and thread rules.
- [x] Pagination and preview models are HWND/printer independent, use explicit
  physical/page/content units, preserve stable page identity, and share one
  rendering contract with the actual print path.
- [x] Print job RAII guarantees balanced StartDoc/StartPage/EndPage/EndDoc or
  AbortDoc behavior under normal return, cancellation, callback failure,
  exceptions, owner teardown, and partial native failure.
- [x] OLE initialization, `IDataObject`, `IEnumFORMATETC`, `IDropSource`, and
  `IDropTarget` helpers define COM identity/reference ownership, FORMATETC/
  STGMEDIUM transfer, delayed rendering, effect negotiation, reentrancy,
  exception containment, revoke-once registration, and apartment/thread rules.
- [x] Typed formats cover CF_UNICODETEXT, CF_HDROP, and registered custom
  clipboard formats without lossy conversion or application pointers in native
  payloads; size/allocation limits are explicit.
- [x] Shell helpers define per-user file-association schemas and reversible
  ownership, notify the Shell after changes, avoid claiming associations the
  app does not own, and expose raw registry/COM escape hatches.
- [x] Jump List and taskbar helpers use stable application identity, explicit
  destination/task ownership, removed-item handling, progress/overlay reset,
  Explorer restart recovery, COM failure results, and deterministic teardown.
- [x] Focused settings helpers support typed/versioned per-user values,
  distinguish missing/malformed/access failure, write transactionally where
  possible, enumerate/remove only owned values, and do not become hidden global
  configuration or invoke application callbacks while holding registry state.
- [x] Public APIs document Windows 10+ availability, ownership, threading/
  apartment requirements, callback lifetime/reentrancy, native units, security
  boundaries, fallback behavior, and cancellation/failure semantics.

## Automated evidence

- [x] Pure tests cover pagination, page ranges, margins/units, preview zoom,
  print transaction states, OLE effect negotiation, format selection, Shell
  identity/association plans, Jump List filtering, taskbar state, and versioned
  settings transitions without printers, COM registration, or Explorer.
- [x] Native print tests use a deterministic virtual/test DC where available
  and controlled fakes otherwise, proving capability reads, balanced document/
  page calls, cancellation, partial failure, callback exceptions, and cleanup.
- [x] Native OLE tests exercise real COM data objects/enumerators, STGMEDIUM
  ownership, delayed data, same-process drag/drop routing, register/revoke,
  wrong-apartment calls, reentrant callbacks, and close-during-drag behavior.
- [x] Shell tests isolate all registry changes under a unique per-user test
  identity, restore/remove state on every exit, inspect real association plans
  and taskbar/Jump List COM calls where available, and use structured fallbacks
  when the hosted desktop lacks Explorer capabilities.
- [x] Stress tests repeatedly create/destroy print jobs/preview resources, data
  objects/drop registrations, registry plans, Jump Lists, and taskbar objects
  with bounded USER/GDI/COM/registry/resource deltas.
- [x] Negative tests cover oversized/malformed payloads, unsupported formats,
  stale/revoked targets, denied registry/printer access, missing printers/
  Explorer, invalid DEVMODE, callback exceptions, and shutdown races without
  dialog hangs or leaked registrations.
- [x] The approved local gate passes with Visual Studio 2026/MSVC x64 in Debug
  and Release, including package consumers and documentation checks. Other
  compilers, architectures, sanitizers, coverage, Pipeline, and GitHub Actions
  remain deferred until after 0.8.

## Packaging, documentation, and Agent evidence

- [x] Core-only consumers do not acquire optional notification dependencies;
  printing/OLE/Shell surfaces have installed-package consumers and remain
  usable through `add_subdirectory`, `FetchContent`, and `find_package`.
- [x] Beginner tutorials build and test printing/preview, OLE drag/drop, and
  Shell integration step by step with Visual Studio 2026/MSVC C++20 x64,
  including non-destructive test identities and precise diagnostics.
- [x] Focused recipes cover adding a printed page, sharing preview pagination,
  adding a custom OLE format, registering a drop target, adding a Jump List
  task, taskbar progress, reversible file association, and a typed setting.
- [x] Capability/example manifests, API index, website, `llms-full.txt`, and
  Win32++ comparison describe every 0.5 surface and identify native ownership,
  apartment, security, reversibility, optional dependency, and fallback rules.
- [x] Agent evals compile golden fixtures for the focused changes above and
  include negative cases for STGMEDIUM/handle transfer, unbalanced print jobs,
  registry overreach, COM apartment misuse, reentrant teardown, and invented
  convenience APIs.

## Completion reflection gate

Before changing 0.5 to `complete` in `docs/parity.json`, create
`docs/reflections/0.5.md` containing the exact required sections:

1. `Requirement evidence` for every checkbox above;
2. `Defects found` during audit and fixes made after apparent completion;
3. `Verification evidence` for the complete approved local gates;
4. known limitations with proof they do not violate 0.5 acceptance;
5. `Thoroughly complete?` with an explicit evidence-backed answer.

0.6 work must not begin until every 0.5 checkbox is complete and the reflection
supports a yes.
