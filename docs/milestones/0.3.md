# 0.3 acceptance checklist — desktop controls and window composition

0.3 is complete only when every requirement below has direct evidence. Existing
thin wrappers do not count unless a representative application proves their
lifetime, state, notification, DPI, and accessibility behavior.

## Product evidence

- [x] A settings application uses resizable pages, validation, Apply/OK/Cancel,
  task-dialog feedback, and persistent settings.
  Evidence: `examples/property_sheet` keeps committed settings outside HWNDs,
  composes two retained-layout pages, marks native edits dirty, validates before
  apply, reports validation/load/save errors with task dialogs, and persists a
  versioned HKCU schema only before replacing committed state. The existing
  property-sheet native suite proves resize and Apply/OK/Cancel behavior;
  `mwtl.settings_application_model` covers missing/round-trip/malformed storage
  using a unique temporary key, while `mwtl.settings_application_gui` drives
  both pages of the real executable and verifies persisted presentation.
- [x] A tray utility proves add/update/remove, context commands, notifications,
  Explorer restart recovery, and deterministic shutdown.
  Evidence: Hot Corners uses `TrayIcon` for stable-GUID registration, typed v4
  activation/context routing, pause/resume tooltip and notifications,
  `TaskbarCreated` recreation, and explicit close removal; its self-test and
  `mwtl.tray_icon_native` execute the real application and Shell protocol.
- [x] A property-sheet example proves multi-page navigation, dirty/apply state,
  validation failure, cancellation, and modeless lifetime.
  Evidence: `examples/property_sheet`, `mwtl.property_sheet_model`, and
  `mwtl.property_sheet_native`, including real tab selection, Apply enablement,
  invalid validation, modal/modeless close paths, 40-cycle resource stress,
  responsive HWND geometry, and cross-thread close dispatch.
- [x] An Explorer-style example composes rebar, toolbar, status bar, splitter,
  TreeView, virtual ListView, tabs, image lists, and context menus.
  Evidence: `examples/explorer` composes every named native control around an
  application-owned stable-ID model, shared commands/accelerators, borrowed
  image lists, forwarded pane notifications, responsive layout, and structured
  popup results. `mwtl.explorer_model` proves filtering/sorting identity;
  `mwtl.explorer_gui` drives the real executable through folder navigation,
  owner-data mapping, sort, F5, tabs, keyboard context routing, accessibility,
  theme/settings messages, pane geometry, and 40-cycle menu resource bounds.
- [x] Every reference application is keyboard operable, accessible, DPI-aware,
  high-contrast aware, distributable, and useful beyond a screenshot demo.
  Evidence: `docs/reference-apps/index.md` maps Settings, Explorer, Hot Corners,
  and Notepad to their executable GUI/native/model/manifest evidence. Their
  command accelerators and native traversal are exercised; GUI tests retrieve
  explicit MSAA names; retained layouts/fonts use DIPs; theme/settings changes
  reapply system appearance, whose tested policy gives High Contrast priority;
  and every executable has an embedded-manifest test. Each application performs
  persisted, document, navigation, or background utility work beyond display.

## Reusable library evidence

- [x] Splitter and tab-workspace APIs define child ownership, stable selection,
  keyboard navigation, resize constraints, and DPI behavior.
  Evidence: `mwtl/splitter.h`, `mwtl/tab_workspace.h`, the common-controls
  gallery, `mwtl.splitter`, `mwtl.splitter_native`, `mwtl.tab_workspace`, and
  the real `TabControl` keyboard/state checks in `mwtl.modern_api`.
- [x] Property-page/sheet APIs define page lifetime, validation, dirty/apply,
  result, cancellation, modal, and modeless contracts.
  Evidence: `mwtl/property_sheet.h`, `docs/api.md`, the property-page recipe,
  independent-header compilation, installed package consumption, and the model
  and native integration suites above.
- [x] Task-dialog APIs expose buttons, radios, verification, progress, links,
  callbacks, cancellation, native errors, and availability behavior.
  Evidence: structured `TaskDialogOptions`, callback events and scoped
  `TaskDialogController` in `mwtl/control_resources.h`; the common-controls
  example; and `mwtl.task_dialog`, which drives the real native dialog through
  custom choices, keep-open, progress/text updates, cancellation, exception
  capture, invalid inputs, availability detection, and 30-cycle resource stress.
- [x] General modal/modeless dialog ownership prevents double destruction,
  use-after-close, orphaned owners, and nested-loop ambiguity.
  Evidence: move-only `mwtl::Dialog`, structured results, explicit borrowed
  owner/thread contracts, the desktop-integration modal form, independent
  header/package consumption, and `mwtl.dialog_native`. The native test covers
  modal/modeless accept and cancel, close veto, ordinary and pseudo-modal owner
  behavior, repeated create rejection, move replacement, callback exceptions,
  cross-thread close dispatch, keyboard traversal, MSAA name retrieval,
  DPI-scaled client geometry, theme messages, and 40-cycle USER/GDI stress.
- [x] Tray-icon lifetime is RAII-safe and covers identity, callback routing,
  recreation after `TaskbarCreated`, notification versions, and teardown races.
  Evidence: move-only `mwtl::TrayIcon` requires stable GUID/ID identity,
  negotiates `NOTIFYICON_VERSION_4`, exposes typed coordinates and keyboard
  events, tracks recovery failure, and deletes idempotently. The native suite
  covers validation, real add/update/hide/show/notification/recreate/remove,
  wrong identity/message/thread rejection, move replacement, owner-first
  teardown, and 40-cycle resource stress.
- [x] Tooltip, image-list, and context-menu APIs make borrowed/owned native
  handles explicit and propagate command/accessibility state.
  Evidence: `Tooltip` owns text/HWND while borrowing owner/tools and supports
  update/remove/title/width/delay/activation/relay; `ImageList` owns its handle
  while toolbar attachment borrows it and supports replace/remove/overlay/
  native sizing; `MenuKind`, `IsOwned`, and `PopupMenuResult` expose transfer,
  selection, cancellation, and failure. The common-controls and Hot Corners
  examples plus `mwtl.control_resources_native`, `mwtl.modern_api`, and
  `mwtl.desktop` verify native state, Command projection, MSAA naming, owner
  transfer, cancellation, and 40-cycle USER/GDI bounds.
- [x] ListView and TreeView APIs cover stable item identity, multi-selection,
  sorting, label editing, notifications, state images, and virtual data without
  forcing application data into control-owned pointers.
  Evidence: nonzero `TreeItemId`/`ListItemId`, typed notification decoders,
  exception-contained comparators, multi-selection, state/edit APIs, and shared
  `VirtualListModel` owner-data projection are implemented in
  `navigation_controls.h`. The common-controls gallery uses stable tree IDs and
  a real virtual ListView. `mwtl.navigation_model` proves identity remapping;
  `mwtl.navigation_native` reads actual HWND IDs/text/state/selection/order,
  captures real `WM_NOTIFY`, services `LVN_GETDISPINFO`, contains callback
  exceptions, rejects duplicate IDs and invalid virtual mutations, and bounds
  USER/GDI resources across 40 create/destroy cycles.
- [x] Selection adapters give ComboBox/ListBox and related controls typed,
  bounds-safe item and selection operations.
  Evidence: `SelectionAdapter<Control, Value>` owns labels/values separately
  from Win32 item data and provides checked add/select/remove/clear/value lookup
  for ComboBox, ListBox, and ComboBoxEx. `mwtl.selection` covers model drift,
  missing values, bounds, removal, and clearing; `mwtl.modern_api` reads real
  HWND labels and selections for all three controls; independent-header and
  installed-package consumers compile the public surface.
- [x] Resizable-dialog layout composes with the normal mwtl layout system rather
  than introducing a second anchor-only layout model.
  Evidence: `Dialog::SetLayout(LayoutNode)` owns an ordinary `LayoutHost`; the
  reference form and native test both use `Column`/`Row`, verify retained resize
  geometry, and preserve DIP client sizing.
- [x] Public APIs document threading, ownership, lifetime, errors, native escape
  hatches, and Windows 10+ behavior.
  Evidence: public header contracts and `docs/api.md` explicitly identify
  owned versus borrowed HWND/HICON/HIMAGELIST state, creating-UI-thread rules,
  callback/view lifetimes, structured errors and Win32 last-error behavior,
  borrowed `GetHwnd`/`GetHandle` escape hatches, and Windows 10+ availability or
  best-effort behavior for every 0.3 family. Independent-header and installed
  package consumers compile the documented surface.

## Automated evidence

- [x] Pure model tests cover splitter constraints, tab selection, page dirty/
  apply transitions, virtual data mapping, stable item IDs, and tray state.
  Evidence: `mwtl.splitter`, `mwtl.tab_workspace`,
  `mwtl.property_sheet_model`, `mwtl.navigation_model`,
  `mwtl.explorer_model`, and `mwtl.tray_icon_state`. The TrayIcon wrapper uses
  the same public HWND-free state model proven by the last test.
- [x] Native integration tests read actual HWND state and notifications for all
  new controls rather than asserting only cached wrapper fields.
  Evidence: `mwtl.modern_api`, `mwtl.splitter_native`,
  `mwtl.property_sheet_native`, `mwtl.task_dialog`, `mwtl.dialog_native`,
  `mwtl.tray_icon_native`, `mwtl.control_resources_native`, and
  `mwtl.navigation_native` query actual styles, text, selection, item IDs,
  image lists, geometry, accessibility, notifications, and Shell results.
- [x] GUI tests cover modal/modeless close paths, validation cancellation,
  keyboard traversal, accessibility names/roles/states, DPI changes, theme/high
  contrast, and Explorer restart simulation.
  Evidence: the native property-sheet/dialog/task-dialog suites cover all close
  and validation paths; dialog and Splitter tests prove keyboard and MSAA
  roles/states; reference GUI tests read MSAA names and drive theme/settings
  refresh; DPI suites verify DIP/native geometry; `mwtl.appearance` enforces
  High Contrast precedence; and `mwtl.tray_icon_native` executes
  `TaskbarCreated` recovery against the Shell.
- [x] Stress tests repeatedly create/destroy pages, dialogs, menus, image lists,
  tray icons, split panes, and virtual views with bounded USER/GDI resources.
  Evidence: property-sheet, dialog, control-resource, tray-icon, Splitter, and
  navigation native suites run 40–100 lifecycle iterations and compare
  `GetGuiResources`; Explorer additionally repeats context-menu creation.
- [x] x64 Debug/Release, ARM64 compile, VS 2022/2026, clang-cl, static analysis,
  ASan-compatible paths, package consumers, and documentation checks pass.
  Evidence: local VS2026/MSVC Debug and Release each pass 104/104 tests. GitHub
  Actions run `31330590815`, attempt 2, passes VS2026 x64 Debug/Release, VS2022
  x64 Release, native VS2022 ARM64 Debug, clang-cl x64 Release compile plus
  compatible tests, VS2026 static analysis, MSVC AddressSanitizer, native source
  coverage, package consumers, and documentation/developer workflow checks.

## Completion reflection gate

Before changing 0.3 to `complete` in `docs/parity.json`, create
`docs/reflections/0.3.md` containing:

1. requirement-by-requirement evidence;
2. defects and design problems found during the audit;
3. fixes made after the first apparent completion;
4. full local and CI test evidence;
5. known limitations intentionally deferred, with proof they do not violate
   0.3 acceptance;
6. a final explicit answer to “is 0.3 thoroughly complete?”

0.4 work must not begin until that answer is supported by evidence and all 0.3
checkboxes are complete.
