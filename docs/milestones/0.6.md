# 0.6 acceptance checklist — modern multi-document workspace

0.6 is complete only when every requirement below has direct evidence. A tab
control that switches HWNDs is not a document manager, and a serialized list of
paths is not a safe session-restore workflow.

## Product evidence

- [x] A multi-document reference application opens, creates, saves, closes,
  reorders, and switches multiple Unicode documents with stable identity and
  independent dirty/undo/selection/view state.
- [x] Active-document commands, status, title, menus, toolbar, accelerators,
  context actions, and close prompts route through one explicit active-document
  context without retaining pointers in native tab item data.
- [x] Documents can move between two top-level workspace windows without data
  loss, duplicate ownership, stale commands, invalid HWND parentage, or forced
  process-global singleton state.
- [x] Session restore persists logical documents and view state, validates
  missing/changed/untrusted paths, restores incrementally, and offers a safe
  empty-workspace fallback after malformed or interrupted state.
- [x] Recently closed documents can be reopened in deterministic order with a
  bounded history and explicit behavior for missing, renamed, duplicate, dirty,
  or already-open paths.
- [x] Coordinated application shutdown handles save/discard/cancel across every
  dirty document and every workspace window without partial teardown after
  cancellation or duplicate prompts for one logical document.
- [x] The reference application is useful beyond screenshots, Per-Monitor V2,
  keyboard operable, accessible at native boundaries, distributable, and has a
  deterministic self-test requiring no user input or public network.

## Reusable library evidence

- [x] Public document/workspace models define stable nonzero IDs, document
  ownership, optional view association, active/selected ordering, dirty and
  close state, recently closed history, and explicit invalid-operation results.
- [x] The model never owns document contents by accident, never stores C++
  pointers in native item data, and permits application-defined documents and
  views without a mandatory base class or Document/View architecture.
- [x] Active-document routing composes with `CommandSet` and supports enable,
  checked, text, shortcut, undo/redo, and status projection without callbacks
  under model locks or hidden global current-document state.
- [x] Tab/workspace HWND adapters project stable logical IDs, preserve selection
  across reorder/rebuild, handle close/reorder/keyboard/accessibility events,
  and document page HWND ownership, parenting, focus, DPI, and teardown rules.
- [x] Cross-window transfer uses an explicit prepare/commit/rollback lifecycle;
  source ownership is retained until destination adoption succeeds, and failed
  transfers restore ordering, active state, focus, and command context.
- [x] Session schemas are versioned, bounded, atomic where possible, tolerant of
  unknown optional fields, reject malformed/oversized state, and separate
  application document restoration callbacks from registry/file I/O locks.
- [x] Coordinated close is a pure inspect/decide/commit workflow that supports
  asynchronous application saves, callback failures, reentrancy, window
  destruction, cancellation, and retry without losing document ownership.
- [x] Public APIs document Windows 10+, ownership, lifetime, UI-thread and
  callback/reentrancy rules, persistence/security boundaries, failure states,
  raw HWND interoperability, and optional document/view composition.

## Automated evidence

- [x] Pure tests cover stable IDs, add/remove/reorder/select, active fallback,
  per-document undo projection, recently closed bounds, duplicate/open-path
  policy, transfer prepare/commit/rollback, session migration, and close plans.
- [x] Native tests cover tab notification routing, keyboard and accessible
  selection/close, focus restoration, HWND reparent/adoption rules, DPI change,
  two-window movement, stale page HWNDs, and teardown in different orders.
- [x] Persistence tests use unique isolated roots/files and cover round trips,
  unknown versions, malformed/oversized/truncated state, missing and externally
  changed files, duplicate identities, interrupted writes, and cleanup.
- [x] Lifecycle/stress tests repeatedly open, reorder, transfer, close, restore,
  undo/redo, create/destroy workspace windows, and cancel shutdown with bounded
  HWND/USER/GDI/registry/file/resource deltas and no stale command callbacks.
- [x] Exception and race tests cover save/restore/route/transfer callback throws,
  close during command dispatch, destruction during transfer, repeated close,
  worker completion after close, and reentrant activation without exceptions
  crossing Win32 callbacks or half-committed ownership.
- [x] The approved local gate passes with Visual Studio 2026/MSVC x64 in Debug
  and Release, including package consumers and documentation checks. VS2022,
  ARM64, other compilers, sanitizers, coverage, Pipeline, and GitHub Actions
  remain deferred until after 0.8.

## Packaging, documentation, and Agent evidence

- [x] Core and optional component boundaries remain explicit; installed,
  add_subdirectory, and FetchContent consumers compile the document/workspace
  surfaces without acquiring unrelated rendering, OLE, or Shell dependencies.
- [x] A beginner tutorial builds the multi-document application step by step in
  VS2026/MSVC C++20 x64 and explains document ownership, command routing,
  transfer rollback, session identity, coordinated close, and diagnostics.
- [x] Focused recipes cover adding a document type, routing an active command,
  independent undo state, a closable/reorderable tab, cross-window movement,
  recently closed history, session restore, and coordinated shutdown.
- [x] Capability/example manifests, API index, website, llms-full, change matrix,
  and Win32++ comparison describe every 0.6 surface, composition boundary,
  ownership/lifetime rule, failure result, and verification command.
- [x] Agent evals compile golden fixtures for the focused changes and include
  negative cases for pointer-backed tab identity, hidden active singletons,
  document/view over-coupling, transfer-before-adopt data loss, non-atomic
  sessions, stale callbacks, and partial coordinated shutdown.

## Completion reflection gate

Before changing 0.6 to `complete` in `docs/parity.json`, create
`docs/reflections/0.6.md` containing the exact required sections:

1. `Requirement evidence` for every checkbox above;
2. `Defects found` during audit and fixes made after apparent completion;
3. `Verification evidence` for the complete approved local gates;
4. known limitations with proof they do not violate 0.6 acceptance;
5. `Thoroughly complete?` with an explicit evidence-backed answer.

0.7 work must not begin until every 0.6 checkbox is complete and the reflection
supports a yes.
