# 0.2 acceptance checklist — real SDI application

0.2 is complete only when every requirement below has direct evidence. A green
general-purpose test suite does not substitute for an unchecked requirement.

## Product evidence

- [ ] `examples/notepad` is a useful, distributable native text editor rather
  than a UI mock-up.
- [x] New, Open, Save, Save As, and Exit operate on real files.
- [x] Dirty state and destructive-action prompts cover New, Open, close-window,
  and Exit paths.
- [x] Canceling a dialog or save prompt preserves the document and application.
- [ ] Cut, Copy, Paste, Undo, Redo, Select All, Find, and Replace work.
- [ ] Menu, toolbar, keyboard shortcuts, and status bar share command state.
- [x] A dropped text file can be opened safely.
- [ ] Recent files and user settings survive restart.
- [ ] A second launch can hand an input file to the existing instance.
- [ ] The example has keyboard-only operation, accessible names, high-contrast
  behavior, and correct Per-Monitor-V2 DPI behavior.

## Reusable library evidence

- [x] Document identity, path, dirty state, and close/save decisions have a
  tested reusable public model.
- [ ] Command state covers enabled, checked, visible, text, and icon without
  duplicating state across surfaces.
- [ ] A native status-bar API participates in layout and DPI updates.
- [ ] File I/O reports cancellation and failures distinctly and never silently
  destroys unsaved content.
- [ ] Settings and recent-file persistence have explicit schema, ownership, and
  failure behavior.
- [ ] Single-instance activation has explicit startup/shutdown race behavior.

## Automated evidence

- [x] Pure document-state tests cover clean/dirty transitions and every close
  decision.
- [x] Temporary-file integration tests cover UTF-8/UTF-16, empty, large,
  missing, read-only, malformed, and externally changed files.
- [ ] Command propagation tests prove every surface reflects the same state.
- [ ] GUI self-tests cover launch, edit, save, reopen, cancel, and close.
- [ ] Resource-leak and repeated open/close stress tests pass.
- [ ] x64 Debug/Release, ARM64 compile, VS 2022/2026, clang-cl, static analysis,
  ASan-compatible paths, package consumer, and documentation checks pass.

## Documentation and Agent evidence

- [ ] Beginner Notepad tutorial starts from a supported template.
- [ ] Public APIs document ownership, threading, lifetime, errors, and native
  escape hatches.
- [ ] `docs/capabilities.json`, `docs/examples.json`, API index, website, and
  `llms-full.txt` describe the shipped surface.
- [ ] An Agent recipe adds a command and a persistent setting to Notepad.
- [ ] Agent evals modify the application correctly without inventing APIs.

## Completion reflection gate

Before changing 0.2 to `complete` in `docs/parity.json`, create
`docs/reflections/0.2.md` containing:

1. requirement-by-requirement evidence;
2. defects and design problems found during the audit;
3. fixes made after the first apparent completion;
4. full local and CI test evidence;
5. known limitations intentionally deferred, with proof they do not violate
   0.2 acceptance;
6. a final explicit answer to “is 0.2 thoroughly complete?”

0.3 work must not begin until that answer is supported by evidence and all 0.2
checkboxes are complete.
